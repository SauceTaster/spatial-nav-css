production toolkit — the parts you reach for when it ships

Each panel is one subpath import doing one production job. Everything here is fully keyboard- and gamepad-drivable: ←↑↓→ move, Enter/Ⓐ activate (hold for long-press), Esc/Ⓑ hub.

🗨 Gamepad-navigable dialogs

import { spatialAlert, spatialConfirm } from 'spatial-nav-css/dialogs'

window.alert() freezes all page JS — gamepad polling included — and a controller can't dismiss it. These render a real <dialog>.showModal() instead: navigation is auto-contained, every adapter works, and the promise resolves on dismissal.

⏱ Long press

document.addEventListener('spatial:activaterelease', e => e.detail.durationMs >= 600 ? hold() : tap())

Activate fires once per physical press (a held Enter doesn't machine-gun clicks); release carries the hold duration. Try tapping vs. holding Enter/Ⓐ on the card.

Tap = play  ·  hold ≥ 600 ms = options

🩹 Focus survives DOM removal

autoRestoreFocus: true // engine default

Press Enter/Ⓐ to delete the focused chip. The engine notices the focused element vanished and restores focus — container memory → default focus → first focusable — without any app code.

🐢 Held-key throttle (TV platforms)

nav.addAdapter(keyboardAdapter({ throttleMs: 150 }))

TV remotes auto-repeat brutally fast. throttleMs gates held-key repeats by time (a fresh press is always instant). Toggle, then hold ↓ through the list and feel the difference.

🔬 Debug overlay

import { attachDebugOverlay } from 'spatial-nav-css/debug' const overlay = attachDebugOverlay(nav) // overlay.detach()

See the page the way the engine does: cyan = focusables (indexed), dashed orange = containers (with their tokens), red = current focus. Repaints on focus, scroll, and resize. Dev-only by design.
